# IP 聚合查询项目目录规划

本项目采用单 .NET 10 API 与 React/TypeScript/Vite 站点，公共首页和 `/console` 后台分别布局。已实现公开协议、六类只读来源（纯真 QQWry 为 IPv4，其余以实际文件地址族为准）和访问日志管线；按[存储结构](spec/后台存储结构草案.md)建立九表 EF 模型、PG 日志及迁移。管理员身份和后台五页业务已接入，管理变更复用既有表与可靠审计，详见[后台管理接口](api/后台管理接口.md)。

公开 [MCP 接口](api/MCP接口.md)：`/mcp` 复用同一查询服务，首页提供接入说明，后台独立 MCP 调用审计页复用访问日志管线；`ACCESS_LOG` 新增可空 `MCP_CONTEXT_JSON jsonb`。

## 职责与约束

- 实体和 DTO 放 `Models/`，interface 放 `Service/`，实现放 `Service/impl/`，公共代码放 `Common/`；所有厂商实现同一 `IIpDataProvider`。按厂商分实现目录，不立即拆多个程序集。
- 纯 IP 路径只做地址识别与非阻塞访问事件入队；日志 Worker 负责批量落库和统计，数据库故障不应进入该响应的等待链。
- 后台数据库用于账号、白名单、版本、审计和访问统计，由部署方显式配置与创建。IP 地理库保持独立文件，不把大 CSV 每请求扫描，也不默认导入后台数据库。
- IP 数据文件、索引、上传暂存、运行日志和私密配置放仓库外专用目录/持久卷；地址通过配置提供，不使用开发者个人文件路径作为默认值。
- 原始供应商数据库不是公共静态资源；不进入 `public/`、镜像源码层、测试夹具或公开下载入口。版本文件不原地覆盖，读取快照释放与清理分开。
- 后台页面、专属资源及 API 都需 IP 白名单，前端路由不能承担访问控制。部署构建时检查专属资源边界，公共共享包不得含秘密。
- 选择一种包管理器并维护其实际锁文件；实际启动和检查命令写入模块 README，不预写不存在的验证入口。

## 设计参考

本项目采用单 API、分类目录和统一 `ApiResult` 的结构，前后端分离、src/tests 分离、根规则与文档分工。公开 MCP 按本项目首页能力独立接入，不照搬其他项目的设备驱动、证书操作、邮件或桌面端能力。

具体调用及错误合同见[查询接口](api/查询接口.md)，上传、安全、存储和性能验收见[一期方案](spec/一期实施方案.md)，许可与来源状态见[数据源文档](spec/数据源与许可.md)。
