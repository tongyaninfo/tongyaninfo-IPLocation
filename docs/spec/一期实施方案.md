# IP 聚合查询一期实施方案

本方案描述当前实现的技术范围与设计约束：公共查询、命令行、多格式 API、公开 MCP、管理员后台、数据库上传、审计与访问量看板。后台存储采用新建 PostgreSQL 并预留 Compose；九表结构和迁移代码已实现，普通 ID 使用本地 `YiteIdService`。实际部署、数据文件与管理员凭据由部署方自行准备。

## 产品与技术方案

- 公共入口默认域名为 `ip.tongyaninfo.com`：浏览器首页自动查询访客 IP，逐源展示已启用数据库的信息，提供手动查询、来源说明和可复制的 API 用法。
- 根路径兼容 curl/wget，纯 IP 输出不依赖定位数据库，但必须记录调用访问元数据，尽量减少请求路径开销。
- 公共 API 使用 `/?ip=xxx&db=xxx&format=json|xml|txt`，省略格式为 JSON；省略 `ip` 识别当前连接地址。无查询参数的根路径保持首页/纯 IP 协商，`/search` 路径保留兼容。完整约定见[查询合同](../api/查询接口.md)。
- 后台入口 `/console`：登录、IP 白名单、各源独立上传与版本管理、访问记录、管理员审计及看板。
- 后端 .NET 10 单 API；前端 React + TypeScript + Vite，公共站采用轻量布局，后台使用 Ant Design 组件与图表。
- 所有厂商实现同一 `IIpDataProvider`；当前公开默认源为 DB-IP City Lite，GeoLite2 停用，纯真支持 QQWry IPv4。IP2Location 为 DB11 IPv4 MMDB；ip2region 及 IPinfo Lite 双栈已接入，定制 Country 不启用；不自动注册或下载数据库。

## 数据源与就绪状态

数据文件不随仓库分发，由使用者按各来源许可自行获取并放到配置路径。数据库未就绪时，查询接口和首页如实返回“未就绪/未配置”状态，不伪造结果。

支持的格式与读取方式：

- **DB-IP City Lite**：MMDB，官方 MaxMind 格式读取器；国家、省州、城市、近似坐标，不含 ISP/ASN。
- **IP2Location LITE DB11**：MMDB（复用 MaxMind SDK，通用 City schema）；国家、省州、城市、邮编、坐标、时区，不含 ISP/ASN。其原 CSV 适配器保留但默认不注册使用。
- **ip2region**：v3 双栈 XDB，国家、省、城市、ISP、国家代码。
- **IPinfo Lite**：MMDB，国家、大洲、ASN 与 AS 组织；不含省市、坐标、时区。
- **纯真社区版 QQWry**：`.dat` IPv4；数据字段以授权包为准。
- **MaxMind GeoLite2 City**：MMDB；默认停用，定制 Country 不启用。

按[官方 DB11 格式](https://www.ip2location.com/docs/db11-ip-country-region-city-latitude-longitude-zipcode-timezone-specification.pdf)，CSV 列为起始 IP、结束 IP、国家代码、国家名称、地区、城市、纬度、经度、邮编、UTC 时差。该库不包含运营商/ASN；时差不能冒充 IANA 时区，零坐标不一律当作缺失。文件 mtime 不能当成官方发布日期。

当前下载包可能仅覆盖 IPv4，不能从 MMDB metadata 的 `ip_version=6` 推断 IPv6 覆盖。国家、省州优先库内中文，城市保留可得原文；邮编、坐标、时区按 MMDB 实际字段返回。来源许可与署名要求见[数据源与许可](数据源与许可.md)。

## 数据源与上传

统一接口的每项结果保留数据库 ID、版本、地址族、实际字段、状态、耗时和许可信息；首页逐源展示，API 支持单源及 `all`，不合并成可下载的复合整库。

上传按来源执行“接收 → 技术校验 → 建立索引/读取器 → 就绪 → 显式激活”。上传完成不等于生效；适配器尚未完成或文件不合格时禁止激活。授权由使用者人工处理，系统不要求许可声明、不判断授权；每步记录操作者、来源、文件大小、SHA-256、实际版本信息和结果。

- 流式接收，限制单文件及总占用、并发任务与解析资源；不把大文件交给小型默认请求上限或一次读入字符串。
- 客户端文件名只作展示，由服务端产生存储名；文件在仓库外、Web 根目录外保存，不允许路径穿越、任意 URL 下载或公开读取。
- ZIP/压缩包支持按需增加，未实现格式直接拒绝，不解压未知附件。
- CSV 校验包含转义、列数、数字边界、IP 范围顺序/重叠、实际地址族、字段缺失及坐标范围；不能按单行逗号拆分冒充完整 CSV 解析。
- CSV 查询在受控导入时建立紧凑范围/偏移索引，用二分查找读取对应记录；不每请求扫描大文件。MMDB/XDB/QQWry DAT 走各自适配读取器。
- 激活采用不可变版本快照，正在查询的请求持有对应版本，完成后才释放读取句柄；并发上传/激活同源串行处理，失败保持当前可用版本。
- 回滚允许仍保存且技术可读的上传版本；版本处置由人工处理，系统不按数据年龄自动停用。清理与自动删除策略由部署方决定。

## 后台访问与审计

白名单是第一道入口检查，管理员登录是第二道身份验证。`/console`、子路由、登录、后台专属资源及 `/api/console/**` 都受保护；公共依赖资源不包含秘密。不能只隐藏页面或只保护前端路由。

白名单支持 IPv4、IPv6 精确地址和 CIDR，使用同一可信代理解析器；空白名单默认拒绝。每次请求核验当前配置，变更后现有会话也不能绕过。保存前展示当前连接是否仍被允许；误配置恢复通过服务器本地配置方式，不设置公开绕过入口。默认配置中的 `192.0.2.0/24`、`198.51.100.0/24` 为 RFC 5737 文档示例网段，部署时须替换。

管理员采用 Cookie 登录、HttpOnly/SameSite 属性、登录限流和写操作防伪；不强制后台使用 HTTPS，白名单内来源可通过 HTTP 管理，HTTPS 请求仍使用 Secure Cookie。不创建默认明文密码、不把任何凭据写入前端。公共首页不提供后台入口，管理员手工进入 `/console`。

审计覆盖登录成功/失败、白名单及配置修改、文件上传、校验、激活、回滚及被拒绝的管理操作，含 UTC 时间、操作人、可信来源、动作、目标、脱敏差异、结果和请求追踪标识。密码、Token、整库、完整请求头不入审计。

管理变更与审计应在同一业务事务或可核验状态流程中保持一致；关键审计无法记录时拒绝关键变更，不向用户报告已生效。来源激活的磁盘和内存状态需可恢复，不能把跨文件/数据库动作声称为天然原子事务。

## 纯 IP 与其他公共请求的访问记录

设计目标：纯 IP 请求也记录访问信息，且优先保证访问速度。方案将普通访问记录和管理员操作审计分开处理。

请求线程只识别 IP、记录必要时间和状态、构造小型事件，执行一次非阻塞 `TryWrite` 放入有界队列。纯 IP 路径不调用定位库、远程发号、数据库、文件落盘或外部日志服务；不等待队列空位，不每请求启动 `Task.Run`。

后台消费者批量写入普通访问日志，并汇总分钟级计数/延迟分布。默认队列容量 10,000，500 条或 1 秒触发批次，均可配置；这些不是已经验证的容量承诺。采集响应完成/取消状态时只作轻量入队，不在响应回调等待持久化。

| 情况 | 公共请求行为 | 后台可见结果 |
| --- | --- | --- |
| 正常 | 立即返回 IP 或查询结果 | 批量写入访问记录及统计 |
| 队列已满 | 不阻塞响应，当前事件可能丢弃 | 丢弃计数、队列占用和统计不完整提示 |
| 存储慢或不可用 | 有界重试/退避，由后台处理 | 写入失败、最后成功时间、积压及丢弃数量 |
| 进程异常退出 | 不承诺保留尚未写入的内存事件 | 标明采集窗口及已知缺口，不能承诺精确恢复丢失条数 |
| 正常停止 | 已接收请求完成后限时排空 | 排空结果及剩余未写数量 |

“响应优先”和“异常情况下每条日志绝不丢失”不能同时由内存队列保证。普通访问尽力记录、故障和丢弃可见；若未来要求完整计费级日志，需要另行设计持久队列及开销预算。正常访问日志不因数据库慢拖住响应，关键管理审计仍采用可靠策略。

开源版默认 `AccessLogging:RetainFullSourceIp=false`：不保存完整来源 IP，按 IPv4 /24、IPv6 /48 脱敏。管理员可在明确隐私与合规要求后显式开启；读取仍受后台白名单及管理员身份限制，并配置保留期限。其他字段为 UTC 时间、HTTP 追踪标识、路由类别、方法、协议、输出格式、HTTP 状态、耗时、来源数据库/版本、浏览器/命令行类别和取消状态。

访问日志可保存 User-Agent、Referer 等排障头的有界白名单快照：凭据头不采集，Referer 去除账户、查询串和片段；旧记录显示未采集。请求路径及查询参数可记录，查询目标 IP 可随路径保存；非敏感参数顺序、重复项及原始转义保留，敏感参数值脱敏，路径超出 JSON 编码 32 KiB 预算时明确标记。复用现有请求头 JSON 元数据，不修改数据库结构；历史不回填。请求体、任意完整头集合和原始响应不采集。TraceId 只作链路关联，不替代业务主键。后台访问记录页支持有界左右方向键翻页，输入控件和加载期间不触发。

需要业务 ID 的记录在消费者或管理路径通过 `IIdService` / `YiteIdService` 调用本地 Yitter.IdGenerator，不需要外部发号服务或认证。统计自然维度可使用分钟、路由等复合键；不能擅自引入 GUID/自增主键替代约定。

日志保留期默认建议普通访问明细 30 天、分钟统计 180 天、管理审计 180 天，均可在配置中调整。自动删除和归档清理默认不执行，由部署方决定。这些是项目日志建议，与 MaxMind 数据库旧版 30 天条款无关。

## 看板与统计口径

后台采用明确的数字卡片、访问趋势、来源对比及运行状态，电脑与手机均能查看。首页及后台统一使用主色 `#013187`、辅色 `#EF8200` 和通研品牌 Logo，配合浅灰底、留白卡片与清晰标签；空数据和不可用来源显示真实状态，不用演示数字填充看板。

| 区域 | 展示内容及口径 |
| --- | --- |
| 总览卡片 | 首页 HTML 请求、纯 IP 调用、逻辑查询、错误率及延迟分位数 |
| 趋势图 | 按分钟/小时聚合的请求、成功与失败；标注 Asia/Shanghai 和时间范围 |
| 来源对比 | 各来源调用量、成功/无匹配/失败/超时、延迟、当前版本和技术状态 |
| 采集健康 | 队列积压、丢弃、写入失败、最后成功时间及采集缺口 |
| 版本与安全 | 上传进度、待激活版本、白名单拒绝和最近管理员审计 |

首页一次 HTML 请求计一次首页访问；随后自动查询是另一条逻辑查询，不能相加后称为 PV。CLI 纯 IP 单独计数；聚合请求计一次逻辑查询，但可能产生多次来源调用。静态资源、健康检查和后台轮询不计公共查询量。请求次数不代表人数，暂不宣称真实 UV。

延迟 p50/p95/p99 来自一致的直方图或明细重算，不对各分钟的 p95 再求平均；报告实际样本窗口和采集缺口。访问记录、统计数据和审计只有获准的后台管理员可读。

## 后台持久化

后台使用 PostgreSQL 保存管理、审计与日志统计，IP 数据文件和索引保持独立。表与约束见[存储结构](后台存储结构草案.md)，九表模型、PG 日志代码和离线迁移已实现；Compose 基础设施模板不包含密码，由部署方提供。

后台数据层有显式开关选择 PG 代码，源码默认使用有界内存；日志批量写入与管理员短事务协调。后续多实例时队列、统计和版本切换需相应设计，不能将当前单进程状态声称为分布式能力；查询 IP 文件不依赖日志数据库可用。

关键事实：

1. 技术栈为 .NET 10 + React/TypeScript/Vite + Ant Design、单 API/单站点、`dbip` 默认库、三种格式和 `db=all`。
2. 使用 PostgreSQL，支持 Compose；九类表结构及迁移已实现。ID 使用本地 Yitter.IdGenerator，配置唯一 `WorkerId`。
3. 开源默认允许 `127.0.0.1`、`::1`（localhost 回环）及 `192.0.2.0/24`、`198.51.100.0/24`（RFC 5737 文档示例网段，部署时替换）；显式空名单仍拒绝。管理员通过受控 CLI 初始化，凭据只在私有配置中使用。

## 验收范围

验收覆盖浏览器/curl/wget（含 HTTP 根路径）、默认 JSON 与三种格式错误、IPv4/IPv6、特殊地址、伪造/多跳代理、未就绪来源及部分失败；后台覆盖所有入口白名单、旧会话、无权限写入和防伪；数据覆盖损坏文件、并发激活、版本恢复、排序及兼容许可字段不阻断操作。

性能验证单独对比启用/关闭访问记录的纯 IP 响应耗时、吞吐及 p50/p95/p99，在队列满、磁盘慢、数据库断开和突发访问时仍验证响应可用。实测后报告开销和日志完整性，不能用“异步”替代性能证据。
