# 公开查询接口

本合同覆盖已实现的首页、命令行及公开查询API。当前默认库为`dbip`，GeoLite2保持停用；纯真QQWry支持IPv4 `.dat`，启用后可查询并显示指定署名。前台隐藏所有停用来源及对应署名。IP2Location使用DB11 MMDB（IPv4），定制Country不启用。无路径或文件不可用时明确返回未就绪/不可用，不静默换库。

## 根路径与访客地址

| 请求 | 计划响应 |
| --- | --- |
| 浏览器 `GET /`，未传 `ip/db/format`，Accept 明确接受 HTML 且优先级较高 | 公共查询首页 |
| `curl ip.tongyaninfo.com` | `text/plain; charset=utf-8`，正文仅为规范化访客 IP 和一个换行 |
| `wget -qO- ip.tongyaninfo.com` | 同上；普通 wget 的正文写入文件，不额外要求用户使用特定头 |
| `GET /?db=all` | 后端识别当前连接地址，返回多源 JSON 查询结果 |
| `GET /?format=xml` | 后端识别当前连接地址，使用默认库并返回 XML |
| `GET /api/ip/me?db=all` | 保留兼容的自身 JSON 查询入口 |

根路径未传 `ip/db/format` 时按 Accept 的媒体类型与 q 值协商；`*/*` 或未指定 Accept 默认纯文本。明确优先 HTML 时返回页面，不以 User-Agent 决定格式。传入上述任一查询参数即进入查询 API，即使 Accept 接受 HTML 也按查询格式响应；其他参数（如 `v`）不改变首页协商。响应设置 `Vary: Accept`、`Cache-Control: no-store`。纯 IP 响应原样输出规范化地址，不添加 IPv6 方括号。

地址来自连接和配置的可信代理链，不信任任意转发头。纯 IP 不访问定位库，但必须进入[访问记录流程](../spec/一期实施方案.md)，不等待持久化或统计完成。无法识别地址时返回明确非 2xx 状态和短文本错误，不输出伪造默认 IP。

示例省略协议时 curl 默认访问 HTTP。部署不得对所有请求无条件 301/308：HTTP 根路径的纯文本请求直接 200 返回 IP。后台不强制协议跳转，白名单内来源可通过 HTTP 或 HTTPS 管理。正式文档优先展示 HTTPS 公共查询命令，并验证两种协议的根路径行为。

## 单 IP 查询

`GET /?ip={ip}&db={database}&format={format}`

- `format` 为可选查询参数，支持 `json`、`xml`、`txt`；省略为 JSON，不根据 Accept 改写。格式名不区分大小写。
- `ip` 省略时，从连接地址及既有可信代理链识别当前请求 IP；显式空值、重复参数或非法 IP 返回400，不静默替换为访问者地址。`db`、`format` 显式为空或重复同样返回400。
- `db` 省略时使用配置默认库，为 `dbip`；指定时只接受已登记 ID。`db=all`保留全部登记来源及停用状态，实际只调用启用、就绪且支持本次地址族的来源；未配置或停用的跳过项不单独造成整体partial。前台只展示`enabled=true`的来源；这不改变API登记清单及显式查询停用来源的错误语义。
- 来源 ID 统一为 `dbip / ipinfo / ip2region / CZ88 / geolite2 / ip2location`。纯真公开编码为大写`CZ88`；旧`chunzhen`及过渡小写`cz88`作为兼容别名接受，响应统一为`CZ88`。登记不代表已上传、已获授权或已启用。
- 仅接受单个 IPv4/IPv6，IPv6 无需方括号，由客户端按 URL 查询参数规则编码；不接受域名、端口、CIDR 或 URL。
- 旧 `GET /search/{ip}[/{format}]?db={database}` 与 `/api/ip/me?db=all` 保留兼容；旧search的格式路径段仍要求小写，根参数格式值不区分大小写。首页及前端实际请求统一使用根路径参数入口。

```sh
curl https://ip.tongyaninfo.com
curl 'https://ip.tongyaninfo.com/?ip=1.1.1.1&db=dbip'
curl 'https://ip.tongyaninfo.com/?ip=1.1.1.1&db=dbip&format=json'
curl 'https://ip.tongyaninfo.com/?ip=1.1.1.1&db=dbip&format=xml'
curl 'https://ip.tongyaninfo.com/?ip=1.1.1.1&db=all&format=txt'
curl 'https://ip.tongyaninfo.com/?ip=1.1.1.1&db=CZ88'
curl 'https://ip.tongyaninfo.com/?db=all'
curl 'https://ip.tongyaninfo.com/?format=json'
```

首页直接展示这些用法、默认库及当前启用来源，不要求进入后台才能了解 API。

首页命令分“我的 IP”和“查询指定 IP”两组，前者的结构化命令省略ip，后者携带ip；各组提供JSON、XML、TXT、已启用来源及ALL（db=all的JSON）标签。“我的 IP”组另含根路径纯IP命令，两组标签独立切换，来源均遵循后台排序与启停。

来源描述中的`licenseReviewMode`、`licenseConfirmed`保留兼容；全部来源的许可和授权由人工处理，这些字段不影响查询资格。`GET /api/providers`及查询来源数组遵循后台保存的数据库顺序，首页卡片及底部署名同序。纯真启用即展示指定署名，包括技术未就绪或本次为特殊地址。停用时，前台卡片、数量和页脚署名依据当前启用列表同步隐藏，旧查询结果不能把停用来源重新带回页面。

## 响应与错误

JSON 使用 ApiResult 的 `success / code / message / data`；XML 以 `ApiResult` 为根元素表示相同字段；TXT 采用 UTF-8 键值文本，表示同一业务状态，区别于根路径的纯 IP。

| 格式 | Content-Type | 约定 |
| --- | --- | --- |
| JSON | `application/json; charset=utf-8` | camelCase 字段，缺失值为 null |
| XML | `application/xml; charset=utf-8` | 正确转义文本，不拼接不可信 XML |
| TXT | `text/plain; charset=utf-8` | 一行一个 `key=value`，来源业务字段为 `sources.<id>.fields.<field>`；换行等字符转义，不发生字段注入 |

成功示例结构为 `data.ip`、`data.addressType`、`data.status` 和 `data.sources[]`。每项来源记录含 ID、实际版本、查询状态、耗时、实际字段及署名/许可链接；未提供的字段保持空值，错误信息不泄露路径、凭据或堆栈。具体字段在实现时固定成 DTO 并验证三种序列化一致。

`data.sources[].fields` 以[后端 DTO](../../backend/src/IpLocation.Api/Models/Responses/IpFields.cs)为准，JSON、XML及TXT使用相同字段语义：

| 字段 | 语义 |
| --- | --- |
| `countryCode / country` | 来源中的国家代码与名称 |
| `continentCode / continent` | 来源中的大洲代码与名称；IPinfo 适配新增的可空字段 |
| `region / city` | 来源中的省州与城市，缺失时不由其他来源填充 |
| `isp` | 来源明确提供的运营商；AS组织名称不直接冒充运营商 |
| `asn / asName / asDomain` | ASN字符串、AS组织名和域名；IPinfo的ASN保留`AS`前缀，新增`asDomain`仅作文本 |
| `latitude / longitude` | 来源中的近似坐标，非精确位置 |
| `postalCode / timeZone` | 来源中的邮编与时区或时差，保留来源实际含义 |

纯真QQWry的region为完整地区原文，isp为网络描述；不能将其误读为结构化省州或单一运营商，不补造其他字段。

上述新增字段为向后兼容的可空扩展，不改变统一响应或默认库。IPinfo Lite只提供国家、大洲和AS信息，不补造省市、运营商、坐标、邮编或时区。

| 场景 | HTTP 与业务语义 |
| --- | --- |
| 非法 IP、未知 db 或不支持的 format | 400，具体错误码；合法格式请求的错误沿用该格式，非法格式错误使用 JSON |
| 查询成功、成功无匹配、特殊用途地址 | 200，以状态区分；特殊地址跳过公网定位 |
| 单库不支持地址族 | 200，来源状态 `unsupported`，不能伪造数据 |
| 已知来源未上传、停用或加载失败 | 单库503，明确 `DB_NOT_READY / DB_DISABLED / DB_UNAVAILABLE`，不静默替换；不再产生许可阻断状态 |
| all 有可用结果或成功无匹配 | 200，整体 `success / partial / notFound`，保留每源状态 |
| all 的已就绪来源全部不支持该地址族 | 200，整体 `unsupported`；没有成功或失败查询，不伪造无匹配 |
| all 所有可查询来源均失败，或没有已就绪来源 | 503；列出来源状态，不能返回假成功 |
| 请求受限 | 429，并提供合理 Retry-After |

所有访客查询响应默认 `Cache-Control: no-store`；后端如建立来源结果缓存，需与访客地址识别分开并按 IP、来源、版本区分。聚合的一次客户端请求只记一次逻辑查询，多源调用单独计数。

## 后台接口边界

公开MCP复用上述查询能力，通过 `/mcp` 提供 `query_ip`、`query_my_ip` 和 `list_providers`；查询工具默认 `db=all`，与HTTP省略db使用配置默认库分别定义。MCP外层按JSON-RPC协议，工具业务内容保留统一语义，具体参数、接入及上下文记录见[MCP合同](MCP接口.md)。MCP无需登录、Token或来源白名单，不改变本节的后台保护。

后台页面位于 `/console`，管理 API 统一位于 `/api/console/**`。页面、登录、专属资源及 API 均进行 IP 白名单检查；登录后的操作仍需身份和权限验证，写请求有防伪保护。上传、激活、回滚、白名单及日志接口不属于公开查询合同，不提供公开整库下载。

当前代码中，不被白名单允许的来源访问`/console`、`/api/console`、`/console-assets`及其子路径或`/assets/console-*`专属资源时，均返回空404及`Cache-Control: no-store`，不输出后台错误码、登录页或跳转。这是统一`ApiResult<T>`之外的传输层例外，不改变公开查询的三格式业务响应。允许来源的身份401、权限403及防伪400保持原语义。

全局歧义路径仍对后台及普通未知路径一致返回400 `AMBIGUOUS_PATH`，不将所有无效HTTP请求改成404。完整门禁合同见[后台管理接口](后台管理接口.md)。
