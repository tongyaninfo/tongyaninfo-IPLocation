# 后台管理接口

后台五页使用同源 `/api/console/**` 接口。所有业务接口先核对可信来源白名单及管理员身份，通过来源门禁后的业务响应使用 `ApiResult<T>`，并设置 `Cache-Control: no-store`。白名单内的管理连接同时支持 HTTP 与 HTTPS；写请求携带防伪 Cookie 和 `X-CSRF-TOKEN`。会话和防伪 Cookie 按请求协议设置 Secure，不取消身份、白名单或防伪保护。业务 ID 为十进制字符串。

## 来源门禁与空404例外

`/console`及其子路径、`/api/console`及其子路径、`/console-assets`及其子路径、`/assets/console-*`专属资源和压缩侧车，均在路由、身份及静态文件处理之前检查同一可信来源白名单；路径大小写和HTTP方法不改变门禁。来源识别仍只信任明确配置的代理链，不直接采信Host、`X-Real-IP`或`CF-Connecting-IP`等伪造头。

来源不被允许时返回普通空404：`Content-Length: 0`、`Cache-Control: no-store`，无JSON、HTML、`CONSOLE_IP_DENIED`、后台说明或登录提示。这是`ApiResult<T>`统一业务响应之外的传输层例外；不设置`Content-Type`、`Location`、`Set-Cookie`、`WWW-Authenticate`、`ETag`或`Last-Modified`。未知后台路径也遵循同一拒绝行为。白名单收紧即时作用于后续请求，已有有效管理员Cookie不能绕过来源门禁。

允许IP继续进入原有业务管线：未登录401、权限不足403、防伪失败400、存储不可用503等语义和统一业务响应保持。空404只用于IP白名单拒绝，不将这些业务错误改成404。

全局歧义路径校验仍先于门禁，对后台和普通未知路径一致返回400及`AMBIGUOUS_PATH`中文JSON，并设置`no-store`；目录段、重复斜杠、反斜杠和编码分隔符的拒绝规则不变。HTTP服务器及上游自身拒绝的畸形请求不由应用门禁转换。相关行为由后端集成测试覆盖。

## 运行总览与记录

| 方法与路径 | 参数与内容 |
| --- | --- |
| `GET /api/console/overview` | `fromUtc`、`toUtc`；完整时间窗的请求总量、首页 HTML、纯 IP、逻辑查询、HTTP 错误、平均延迟、p95 桶上界估算、公共趋势、独立MCP总量/趋势、当前进程队列健康、最近审计 |
| `GET /api/console/access-logs` | `fromUtc`、`toUtc`、`sourceAddress`、`routeCategory`、`database`、`format`、`statusCode`、`page`、`pageSize` |
| `GET /api/console/mcp-logs` | `fromUtc`、`toUtc`、`sourceAddress`、`toolName`、`resultCode`、`traceId`、`page`、`pageSize`；固定读取 MCP 路由明细，返回受控上下文和当前队列健康 |
| `GET /api/console/audits` | `fromUtc`、`toUtc`、`actor`、`action`、`result`、`traceId`、`page`、`pageSize` |

未指定时间时读取最近24小时，每次窗口最长31天；明细保留天数为正数时同时受该年龄读取边界约束，为`null`时不设置年龄截止，为`0`时停止新增但已有历史仍可查询。`0`和`null`均不解除单次31天窗口、分页及超时限制，也不删除历史。审计读取边界180天。页码1至1000，每页1至100条，按时间及业务ID稳定排序。时间参数采用带时区的 ISO 8601；界面按 Asia/Shanghai 展示。

总览在 PostgreSQL 对完整窗口求和，不使用有行数截断的历史快照求总量。分钟统计返回实际取整后的桶边界，最新一分钟可能尚未完成写入；延迟直方图合并后计算 p95，无样本或超出最高有限桶时返回空值。请求数不表示用户数，`db=all` 一次逻辑查询不表示一次来源调用。逐来源实际调用、命中、无匹配及超时计数尚未采集。

总览合同包含以下字段：

| 字段 | 内容 |
| --- | --- |
| `mcpTotals` | `{requests, queryRequests, httpErrors}`，为完整查询时间窗内MCP类别的HTTP请求、定位工具请求及HTTP错误总量 |
| `mcpTrend` | `[{timeUtc, requests, queryRequests, errors}]`，实际分钟时间桶的MCP HTTP请求、定位工具请求及HTTP错误 |

两者复用同一PostgreSQL分钟聚合读取，以 `routeCategory=mcp` 筛选，不新增表或扫描截断明细页计算总量。`queryRequests`仅计识别为 `tools/call` 的 `query_ip / query_my_ip` 定位工具请求，包含参数/协议错误（如HeaderMismatch），不表示实际来源调用；不将目录/发现/初始化请求算作定位。`httpErrors / errors`只计HTTP4xx/5xx，HTTP200的工具或业务失败仍在MCP明细中查看，不混作HTTP错误。

公共和MCP趋势图复用SVG交互：悬浮或触摸时十字线连续跟随当前位置，X/Y轴读数表示当前图表坐标；同时提示最近实际时间桶的上海时间与两条曲线真实值，不能将十字线坐标误当作该位置有一条观测记录。键盘左右键、Home/End可切换真实桶，Esc关闭。缺失桶不补零，数据提示不通过伪造插值生成。无数据、单点和采集缺口继续如实展示，不把曲线连续外观当作持续采集或真实人数的证明。

访问记录新增可空`requestHeaders`，结构为`{headers: Record<string,string[]>, truncated: boolean, requestPath?: string, requestPathTruncated?: boolean}`，保存经过白名单过滤及大小限制的User-Agent、Referer等排障头，以及下文获准的路径元数据；路径另由访问记录顶层字段提供。头名小写、多值保留数组。凭据头不采集，Referer/Origin移除账户、查询串和片段。旧记录或无可用快照返回null，页面显示“未采集”；来源定位另以`sourceLocation`返回，包含provider、version、status、country、province、city、isp及rawLocation，只在后台日志消费者使用CZ88解析来源地址，不使用查询目标。不保存任意完整请求头、请求体或原始响应。审计差异在读取时再次按固定字段白名单脱敏；未知字段、密码、路径、连接信息和令牌不透传。数据库未配置或故障返回503，不将进程内窗口当作 PostgreSQL 历史。

2026-11-04追加请求路径字段，普通访问每行DTO增加顶层 `requestPath: string | null` 与 `requestPathTruncated: boolean`。`requestPath` 保存请求path及查询串，例如 `/?ip=1.1.1.1&db=all&format=json`；保留非敏感参数顺序、重复项和原始转义，不包含协议、域名或片段。Token、密码、密钥、授权、Cookie、会话、凭据、签名等敏感参数值替换为 `[REDACTED]`，不将自由文本内容识别能力扩大为任意秘密检测保证。路径按JSON编码后32KiB限额，超限保留有界文本并设置 `requestPathTruncated=true`；历史未采集路径为null，不回填。

持久化复用 `ACCESS_LOG.REQUEST_HEADERS_JSON` 结构中的 `requestPath / requestPathTruncated`，请求头原8KiB预算独立保持，不新增列或迁移；请求头白名单仍只用于头字段。该要求明确允许查询目标出现在请求路径中，不扩大既有公共访问路由采集范围、请求体和原始响应范围，也不改变非阻塞入队、后台批写、保留开关及后台访问控制。

访问记录页列表展示路径摘要，展开详情展示全文，按纯文本渲染并显示截断或未采集状态。左右方向键分别切换上一页/下一页，第一页与末页不越界；加载中、输入或使用方向键的交互控件、修饰键组合、重复按键和已处理事件均不触发。

## MCP 调用审计

`/console/mcp-logs` 是后台独立页面，仍先核对来源白名单和管理员身份。公开 `/mcp` 不需要登录、不设来源限制，与受保护日志读取是两条边界，不能据此公开日志。

`GET /api/console/mcp-logs` 复用普通访问日志的31天单次窗口、保留边界、超时和稳定分页。响应 `data` 为 `items / total / page / pageSize / fromUtc / toUtc / retentionDays / queue`，每行复用访问元数据，并增加可空 `mcpContext`。筛选参数为表中所列字段，不接收任意 JSON 查询条件。

`mcpContext` 的白名单字段：

| 字段 | 语义 |
| --- | --- |
| `protocolVersion / method / requestId` | 实际收到的协议版本、JSON-RPC 方法和请求 ID，缺失为 null |
| `toolName` | 实际调用工具名 |
| `clientName / clientVersion` | 调用方自报信息，不能作为可信管理员或用户身份 |
| `ip / database` | 受控摘要字段，标量IP仅保存合法规范化地址；新input快照可保留有界无效参数文本 |
| `resultCode / resultStatus / isError` | 业务或协议结果，HTTP 200 中的工具失败仍须明确显示 |
| `sources` | 最多6项 `{id, version, status}` 来源摘要，不保存完整查询输出 |
| `input / output` | 清洗后的调用参数/输出JSON快照或null，旧日志为null；正常工具输出优先structuredContent，等价文本回退不重复存储 |
| `inputTruncated / outputTruncated` | 对应快照是否因有界清洗发生截断，超限保留合法JSON |
| `inputCaptured / outputCaptured` | 是否实际采集快照；为true且值为null表示已采集JSON null，为false才是未采集，旧记录false |
| `truncated` | 上下文已清洗或截断，可能仅为SDK_meta过滤，不能据此认定业务字段丢失 |

输入8KiB、输出32KiB、总上下文48KiB，按UTF-8序列化大小计算。每个快照递归深度12、每容器64项、最多1024节点、字符串4096字符；超限标记相应截断字段并合并至顶层 `truncated`。敏感key值统一为 `[REDACTED]`，递归排除 `_meta`，协议错误data/details/stack等诊断内容不透传；业务ApiResult.data不因此全部丢弃。方法、请求ID、客户端等既有摘要字段继续限长/清洗控制字符，读出时再次清洗；旧日志新字段为null，不回填。完整原始HTTP请求/响应、凭据和完整聊天不在采集范围，已有安全请求头及来源地址定位继续使用独立字段。该扩展复用已有jsonb列，无DDL或迁移。

敏感字段替换、绝对HTTP/HTTPS URL去账户信息/查询串/片段、_meta/诊断字段排除同样标记相应快照及顶层为已清洗或截断，不能将该标记仅解释为字节超限或业务数据丢失；SDK_meta清洗后的structuredContent仍可能完整。干净URL、中文及非URL无效IP文本保留，不声称能够识别任意自由文本秘密。等价text回退去重不单独标记截断。页面以Captured区分未采集与JSON null，不借缺失值伪造空对象。

`tools/call.input`仅为实收arguments，省略时为 `{}`；其他方法为清洗后的params，排除_meta。无效/超限JSON无法解析时input为未采集，不留原文；能解析的无效工具参数可以出现在本轮获准的有界input中。`output`保存实际JSON-RPC result或error对象内容，不重复jsonrpc/id外壳；工具结果优先保留structuredContent并去重等价content.text。关闭普通访问采集时不捕获input/output；排队前统一清洗序列化，保留原非阻塞入队与后台批写边界。

`queue` 沿用 `received / accepted / written / dropped / writeFailures / queued / inFlight / isAccepting / lastSuccessUtc / lastFailureUtc / suppressed`，表示当前进程的普通访问管线健康，不是仅该筛选或仅 MCP 的计数。页面展示丢弃、积压和最后成功时间，不把尽力记录等同于可靠管理员审计。`retentionDays=0` 表示已停止新增 MCP 和其他普通访问记录，历史仍按合同查询；`null` 不限制年龄读取，但仍受单次窗口、分页和容量边界约束。

MCP HTTP 请求包含协议发现、初始化、目录和工具调用，只有已识别的定位工具请求计入逻辑查询，参数/协议错误不排除，不等于来源实际调用。完整公开工具合同见[MCP接口](MCP接口.md)。首次 MCP 实现通过 `20261103140118_AddMcpCallContext` 迁移新增 `ACCESS_LOG.MCP_CONTEXT_JSON` 可空 jsonb；后续入出参扩展复用该列，无新迁移。Web 启动不自动迁移。

## IP 数据库

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/console/databases` | 有序来源真实状态、启停、地址族、版本、Revision、displayOrderRevision、上传任务及版本历史；不返回文件存储路径 |
| `POST /api/console/databases/order` | JSON：全量有序`providerIds`及`revision`（来自displayOrderRevision），所有登记ID恰好一次 |
| `POST /api/console/databases/{id}/state` | JSON：`enabled`、`revision`、可选 `defaultDatabase` |
| `POST /api/console/databases/{id}/uploads` | 流式 multipart：`file`、`addressFamily`；不要求授权字段 |
| `POST /api/console/databases/{id}/activate` | JSON：`versionId` 字符串及当前来源 `revision`；激活仍可用的旧上传版本即回滚 |

纯真管理ID统一为`CZ88`，旧`chunzhen`管理路径和排序输入继续兼容。现有版本、活动指针、上传任务及`provider.chunzhen.enabled`使用原存储编码，通过集中映射读取，不搬迁记录。公开/后台列表、默认库及排序输出均使用`CZ88`；旧访问记录编码也在筛选和展示时兼容。

支持 GeoLite2 City、IP2Location DB11、DB-IP City Lite、IPinfo Lite 的原始 `.mmdb`，以及 ip2region 的 `.xdb`、纯真QQWry的IPv4 `.dat`。ip2region 按 IPv4/IPv6 分别上传激活，保留另一地址族的当前文件；IP2Location 当前适配器仅支持 IPv4。不接受 ZIP、CSV 或任意 URL 下载。

文件扩展名只作为初步检查，实际由对应读取器校验来源类型、文件结构、地址族及版本。文件流式写入并计算SHA-256；校验成功登记不可变版本，上传完成不会自动激活。上传不提供授权勾选、依据输入或授权校验；授权由人工处理。新版本保存`LicenseConfirmed=false`及`LicenseEvidenceJson={"reviewMode":"manual","systemVerified":false}`，不宣称系统已确认授权，技术校验通过即可激活。激活前重新检查内容摘要及读取器就绪状态，不按许可或数据年龄停用。配置版本只读引用原文件；可回滚列表为已上传并登记的可用版本。

来源变更与审计同事务；Revision不匹配返回409。停用默认库必须明确选择其他已启用且就绪的默认库。新请求使用已发布快照，在途请求持有对应句柄至完成。进程启动恢复持久化指针；失败时状态明确不可用。所有来源的启用只保存管理员意图，技术未就绪也可启用并明确展示状态；查询和设为默认库仍要求技术就绪。兼容许可字段不参与任何资格判断。纯真QQWry `.dat`已接入，支持IPv4、GBK及直接/重定向记录，日期不补造时间；CZDB和IPv6不在本次能力范围。

数据库顺序使用既有SYSTEM_SETTING的`provider.displayOrder`保存全量ID数组及独立Revision，和`database.reorder`审计同事务提交。未知、重复或缺失ID返回400；Revision冲突返回409 `DATABASE_ORDER_CONFLICT`。保存后公开来源列表、查询来源、后台列表、首页卡片和底部署名立即同序，重启恢复；停用项在前台过滤后保持相对顺序。新登记来源自动补到保存顺序末尾。

非敏感 `Uploads` 配置：

| 配置 | 默认与限制 |
| --- | --- |
| `StorageRoot` | 当前用户 LocalApplicationData 下的 `Tongyan/IpLocation/databases`；必须为仓库和 Web 根目录之外的绝对路径，不接受符号链接路径 |
| `MaxFileBytes` | 1 GiB，最大允许1 GiB |
| `MaxTotalBytes` | 4 GiB，最大允许4 GiB且不小于单文件限制 |

同一管理PG通过会话锁限制同时接收/校验一个上传任务，进程内同时有非阻塞闸门。客户端文件名不参与存储路径，由服务端业务ID生成文件名；最多两个multipart段（文件及地址族），禁用MVC表单预读，写请求须显式提供防伪请求头。失败或中断文件保留并计入容量；达到容量后拒绝继续上传，不自动清理，删除仍须具体授权。反向代理还须配置相应请求体上限与超时。

## 系统设置

`GET /api/console/settings` 返回 `revision`、`query`、`allowedNetworks`、当前可信来源 `currentSourceAddress`、来源列表、可编辑基础配置 `basic`及非敏感运行状态 `runtime`。数据库连接、供应商凭据、密码和密钥路径不返回前端。

`POST /api/console/settings` 接收：

```json
{
  "revision": 1,
  "query": {
    "defaultDatabase": "dbip",
    "providerTimeoutMs": 2500,
    "totalTimeoutMs": 5000,
    "maxConcurrentSources": 4
  },
  "allowedNetworks": ["127.0.0.1", "::1", "192.0.2.0/24", "198.51.100.0/24"],
  "basic": {
    "accessLogRetentionDays": 30,
    "retainFullSourceIp": false,
    "sessionMinutes": 480,
    "queueCapacity": 10000
  }
}
```

默认库必须已启用并实际就绪，任何来源不受兼容授权字段阻断；单源截止时间1至60000ms、整体截止时间1至120000ms且不小于单源时间，并发1至6。白名单支持单IP或规范CIDR，最多128条，保存时必须继续允许当前可信连接；持久化白名单模式下空列表始终拒绝，不回退配置默认名单。

写入前在事务内重新检查管理员启用状态及安全版本，设置和可靠审计同事务提交。保存后整体发布运行快照，后续请求立即使用新的查询参数和白名单；重启加载已保存设置。Revision 冲突返回409，不能覆盖其他操作刚提交的配置。

基础配置单独使用`basic`字段，不能将整个`runtime`作为写入对象。兼容旧客户端省略`basic`时保留当前基础配置；显式`basic.accessLogRetentionDays: null`表示不设时间截止，不能回退为启动默认值。基础配置复用既有`SYSTEM_SETTING`，与`console.settingsRevision`和`Settings.Update`可靠审计同事务提交，无数据库结构变化。

| `basic`字段 | 类型与作用 | 生效边界 |
| --- | --- | --- |
| `accessLogRetentionDays` | `0..365`整数或`null`；正数按天限制明细读取，`null`不设年龄截止，`0`停止新增普通访问日志 | 保存后新公共请求即时使用；历史暂留且仍可查询 |
| `retainFullSourceIp` | 布尔值；关闭时IPv4按/24、IPv6按/48脱敏 | 保存后的新事件使用；不回写已有记录 |
| `sessionMinutes` | `5..1440`整数，管理员会话分钟数 | 仅影响保存后的新登录；不改已有Cookie的签发到期时间 |
| `queueCapacity` | `1..1000000`整数，访问日志有界队列的目标容量 | 已保存但重启后生效，不在线重建或无界扩容队列 |

`runtime`继续展示实际生效信息：`recentEventRetentionDays`为整数或`null`，`sessionMinutes`为新登录当前使用值，`queueCapacity`为本进程实际队列容量；新增`queueCapacityRequiresRestart`布尔值，与`basic.queueCapacity`对照显示是否待重启。后台存储模式、可信代理计数和转发链摘要、配置修订号继续只读，不开放凭据、连接、密钥路径或可信代理修改。

`accessLogRetentionDays=0`时，新普通访问不采集完整来源IP、请求头或来源定位，不入队、不写访问明细，普通分钟统计随该采集流程停止。消费者和存储会再次检查策略，队列中被跳过的事件不能计为成功落盘。保存前已经开始提交的批次允许完成；关闭策略不是排空所有在途提交的同步事务屏障。初始化、登录、退出、配置变更和上传等可靠管理员审计继续运行，设置保存本身仍需可靠审计成功。

当前策略不执行PG历史记录删除或自动清理；正数读取窗口不能作为已物理销毁过期数据的证明。恢复为`null`或正数后，已有历史按新的读取边界可见，新普通访问恢复采集。内存模式仍有条数上限且进程退出后丢失，不将`null`宣称为无限容量或持久化保证。

当前没有日志物理删除、密钥编辑或管理员凭据修改能力。请求头和来源定位字段由 `20261103052149_AddAccessRequestMetadata` 迁移新增两个可空 jsonb 字段；Web 启动不自动迁移。
